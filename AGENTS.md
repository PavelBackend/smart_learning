# Smart Learning: карта для разработчика

- Начни с `docs/architecture.md` для границ сервисов и инвариантов обучения. Команды запуска и пользовательские сценарии описаны в `README.md`.
- Репозиторий может содержать незакоммиченные изменения и реальные данные пользователя. Не сбрасывай рабочее дерево, не очищай Docker volumes и не меняй реальные слова/прогресс ради тестов.
- Запуск из WSL: `make up` собирает образы, применяет Alembic миграции, поднимает сервисы и печатает URL. `make down` останавливает контейнеры, сохраняя данные.
- Бэкенд: `services/<name>/src/api` — HTTP, `services` — правила, `repositories` — SQL, `schemas` — Pydantic. Общие контракты — `shared/contracts`; избегай импортов внутренних модулей одного сервиса в другой.
- Миграции обязательны для схем БД; не создавай таблицы через SQL bootstrap. Зависимости задаются в `requirements.in` и закрепляются через `make lock` (`pip-compile`).
- Фронтенд: `frontend/src/pages`, `components`, `api`, `styles`, `types.ts`. Проверка: `cd frontend && npm run build`. Python: `.venv/bin/ruff check shared services tests` и `.venv/bin/python -m unittest discover -s tests -v`.
- Перед завершением изменений API пересобери контейнеры через `make up`, проверь реальные ручки через `http://localhost:8080/api`, а также отсутствие 502. Не отправляй тестовые ответы по реальным карточкам пользователя.
- Время ежедневного отчёта берётся из часового пояса браузера. Резервные копии и произношение описаны в `README.md`.
